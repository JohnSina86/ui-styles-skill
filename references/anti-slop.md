# Anti-slop tells

Named tells of a default AI-generated page: what each one is, why it reads as generic, and the fix in this skill's own vocabulary (tokens, styles, composition moves, guardrails). Run it on every page you deliver, after the composition moves and before the section 7 checklist.

**Scope.** These are prevalence observations: patterns that appear on a large share of default AI-generated sites. They are not detection methods. None of them proves a page was generated, and none proves it is bad; a deliberate page can carry one for a reason. That is why every tell has an applicability exception tied to the brief or to a token block's documented use, and why a count needs the evidence named in its row. **Sources:** the hyper.ai summary of Adrian Krebs's analysis that scored 15 patterns across 500 Show HN landing pages (hero badge with Inter, gradient backgrounds with glass cards, coloured left borders, icon-topped feature grids; its manual check put false positives at 5 to 10%, which is the reason for the exceptions), the dev.to piece "Why do AI-generated websites all look the same", Search Engine Journal's "7 common AI website mistakes that are easy to avoid", and tells seen in this skill's own outputs. Summaries, not research.

**Rubric v1.3** (2026-10-13). The table is frozen. A benchmark that scores a page records this version, and any change to a row, its severity, exception, evidence rule or counting unit is a new version with a new number. v1.1 to v1.3 replaced v1 the same day, before any output was scored. v1.1 added the Inputs rule, exempted the token blocks that alias `--ui-text` and `--ui-accent`, required provenance rather than brief membership for images, and counted unsupported proof per attribution. v1.2 added the retained disposition for kept design-system choices, counted text set in the accent role, and tied the reveal exception to compliance with the brief's budget. v1.3 limited retained to aesthetic rows, tied the icon-card-grid exception to the assessed occurrence, and listed the evidence accepted for exceptions in one place.

## How to count
- **Inputs.** The predicates need three things: the delivered source, the verbatim brief with its content pack (the copy, images, customers, quotes and figures it supplied), and a render if one was made. Every exception claimed records its reference: the brief line or content-pack item, or the token block and property it rests on. Without the brief and content pack, the rows whose *Not a tell when* or *Evidence* names them (`hero-centred-stack`, `hero-badge`, `icon-card-grid`, `fake-logo-row`, `stock-imagery`, `emoji-icons`, `interchangeable-copy`, `fade-in-everything`, `invented-proof`, `placeholder-footer`) are reported as **unassessable: no brief**, neither counted nor cleared. The other rows are assessed from source and render alone.
- **Severity.** `high`: on its own it makes the page read as a template, or it asserts something untrue (logos, quotes or numbers the brief never supplied). `medium`: it adds to the template look, and one instance with a stated reason is tolerable.
- **Applicability.** A tell is not counted when its *Not a tell when* condition holds and you record the reference in the delivery note: the brief line or content-pack item, or the token block and property. An exception you can't point at is not an exception. No exception ever asks you to change a verified palette: a tell is cleared by moving colour, type or content, never by editing a ledger row.
- **Retained.** An aesthetic row (colour, gradient, radius, shadow, type, layout, motion) can be a kept choice of the project's existing design system (section 0) or a constraint the user set: a brand's purple-blue gradient, its one sans, its soft cards. Such a tell is **retained**, not counted and not cleared. Record it with a user constraint record (below). Retained tells pass the delivery gate but are listed under their own "Retained" heading with that record; a page with retained tells is never reported as having no tells, and a retained tell is never restyled silently. Proposing a change to it goes through section 0: propose, and apply only if the user agrees. **Rows that assert facts can never be retained:** `fake-logo-row`, `invented-proof` and `placeholder-footer`. An existing component with an unsupported customer, quote, figure or page claim stays counted at its severity. When the user must approve its removal, it is also flagged **unresolved: pending evidence**, with the claim and the evidence that would clear it; it still counts until that evidence arrives or the claim is removed.
- **Evidence.** Count a tell only when the *Evidence* in its row is visible in the source or in the render. "Looks like it" without that evidence is a note, not a count. Say which you used. Source is always available; "render" only after a browser render in this session (section 7 checklist).
- **Unit.** *Pattern* tells count once per page, however many sections show them. *Element* tells count once per occurrence: each grid, each gradient, each logo row. A page is one route or view, so report multi-page work page by page.
- **Where the counts go.** Tells are craft findings. Report them under their own heading in the delivery note, never as a `ux-laws` law row or score. The laws grade structure and behaviour, and a tell is neither.

## Evidence accepted for exceptions and retained dispositions
Versioned with the rubric. An exception or retained disposition that cites none of these is not accepted, and the tell counts.
1. **Brief reference:** the brief line or content-pack item, quoted, with where it sits (section or item). Clears a *Not a tell when* that names the brief; for `icon-card-grid` it must name the occurrence it clears.
2. **Token-block reference:** style id, file and property (`bento-grid`, `tokens-graphic.md`, `--ui-radius`). Clears a *Not a tell when* that names a token block or its documented decorative use.
3. **Catalog recipe reference:** style id and the `styles-catalog.md` section applied. Clears `glass-over-gradient` and the control-distinctness part of `accent-everywhere`.
4. **Asset provenance record:** for an image, one of: the content-pack item; the route, viewport and date of a screenshot taken during the build; the path of an existing project asset and what it shows. Clears `stock-imagery`.
5. **User constraint record:** the user's words, quoted, that keep an existing design-system choice, with the existing token or rule it rests on. Retained dispositions only, aesthetic rows only.
6. **Reveal budget record:** the brief's budget line, the named choreographed sections and their count against it. Clears `fade-in-everything`.

## Could this be any site?
Answer each question in one sentence with its evidence before delivery, under their own heading in the delivery note. A question you can't answer with evidence gets "no evidence", not a guess.
1. **Copy.** Cover the brand name and logo. Does the headline still say what this is and who it is for? Name the words that do it.
2. **First screen.** Name the one huge thing and the one thing in the accent on the first screen. If you can't name one of each, or there are two of either, say so.
3. **The thing itself.** Where on the page is the actual product, place or person (a real screenshot, the brief's photo, the real menu)? Name the section.
4. **Shape.** Scrolled at 1440 with the text unreadable, which two sections differ in shape from the rest, and how?
5. **Style.** Which indexed style is this, and which three choices (type pairing, surface shape, backdrop or imagery) came from its token block rather than a framework default?

## Checks
Add these to the section 7 checklist for every page you deliver.
- [ ] Every rubric row checked against the source, and against a render if one was made this session. Counts reported per page by id and severity, with the unit used.
- [ ] Zero high tells. At most two medium tells per page, each named with the reason it stays. Retained tells listed under their own heading with the existing token or rule and the user's constraint, outside the counts and never described as no tells.
- [ ] Every exception or retained disposition cites one of the accepted evidence types, for the specific occurrence it clears. Rows that need the brief are marked unassessable when it is missing, not cleared. Factual rows are never retained; unresolved claims stay counted.
- [ ] The five questions answered, one sentence of evidence each, in the delivery note.
- [ ] Tells and answers sit under their own heading, never in a `ux-laws` table or score.
- [ ] "Checked in render" only after a browser render in this session; otherwise "source only", with the render-only evidence left open.
- [ ] The rubric version is named: anti-slop rubric v1.3.
